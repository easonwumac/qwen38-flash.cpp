# Daily-use baseline and closeout — 2026-09-19

Decision: close the optimization phase at the user's request and retain the
existing VQ runtime for daily use. No kernel, numerical policy, checkpoint,
MTP setting or runtime default changed in this documentation milestone.
This is not a new speed record, proof of a hardware limit, or certification of
all context lengths. Future research is deferred, not automatically scheduled.

| Component | Daily baseline |

| State/scheduling | Automatic QSA, Q8 KV, bounded adaptive prefill, prefix reuse, up to four independent request slots |
| Default resource limits | 8,192-token RAM prefix cache; 4,096 generated tokens; user may change these resource budgets |
| Guarded launch | 42 GiB start admission, 6 GiB available-memory floor, 38 GiB RSS / 40 GiB footprint stop thresholds |
| Validation platform | M5 Pro, 18 CPU cores, 64 GiB, macOS 26.5 (25F71), MLX 0.32.2; AC power, no active thermal conditioning |

The memory guard is a polling watchdog, not a hard allocator ceiling. An
oversized request can be terminated and transient overshoot is possible.
Do not disable the guard to reproduce a headline number. Sampling/thinking and
cross-request batching can bypass MTP; missing sidecars select target-only.

## Accepted evidence, not fresh measurements

The [README scorecard](../README.md#current-vq-evaluation) is the short view.
The [detailed benchmark archive](benchmark-history.md),
[results guide](results-guide.md) and
[full quality qualification](vq-quality-preserving-2026-09-19.md#full-quality-qualification)
retain model/sampling/MTP/context/corpus and distribution boundaries.

- PP: 455.45 cold / 519.91 warm tok/s on the old hashed 7,091-token repository
  corpus, one cold/warm pair, cache/MTP off. Editing README does not create a
  comparable replacement corpus.
- Target-only: 30.59 tok/s median across three fixed-input 64-step starts;
  native MTP: 57.94 median on the favorable 64-output coding fixture with Q6
  sidecar and Q4 draft head. These are not universal HTTP throughput figures.
- HumanEval original tests, greedy/no-thinking full-program chat, max 768:
  native MTP 146/164, target-only 147/164. MTP aggregate decode is 46.93 tok/s;
  per-request median 48.41 [P10 42.87, P90 54.77] in one serial sweep. Zero
  HTTP errors, eight length-limited MTP answers; not HumanEval+.
- IFBench: native-MTP first-30 strict/loose 18/30, max 4,096, greedy/no-thinking;
  first-ten sampled bounded-xhigh pilot 8/10, MTP bypassed. Neither is full
  IFBench and they do not establish general superiority over 27B.
- Long context: 32,024 input / 29 output tokens, greedy/Q8 KV/MTP off,
  22.68 decode tok/s at 39.5 GiB. **VQ 128K is unqualified.**
- Retained qualified footprint range: 36.3–39.6 GiB, workload dependent.

Different serial and batched floating-point paths can change token trajectories.
Quality gates, rather than a promise of target-only token identity, qualify
the existing MTP configuration. Historical REAP/Niwaki results remain references
and must not be presented as VQ results.

## What closes, and what remains unachieved

| Area | Disposition |
|---|---|
| Daily runtime | Retain current automatic configuration; no extra profiles or experimental switches |
| Correctness work | Keep QSA rollback, native EOS/state-handoff and native QSA selector fixes with regression tests |
| Persistent target verifier | Rejected after paired S=5 regression; prototype removed; production verifier unchanged |
| Compact verifier / GPU-indirect prefill | Rejected after full-path tests; preserve reports, not dead implementation branches |
| 600 PP / 40 target-only / 60 mixed-workload MTP | Not achieved as a combined requirement; deferred, not release claims |
| VQ 128K / model-declared 262K | Not qualified; older checkpoint capacity results do not fill this gap |
| Native persistent MTP integration and Q8 capacity management | Not promoted / deferred; state correctness work alone is not complete integration |
| Full VQ IFBench and long-duration unattended qualification | Incomplete; existing pilots and earlier lifecycle evidence retain their original scope |

See [latest verifier report](persistent-verifier-2026-09-19.md),
[production-dataflow report](vq-production-dataflow-2026-09-19.md), and
[research ledger](prior-research-ledger.md) before revisiting a rejected route.
Reopen research only for a concrete new hypothesis with paired end-to-end,
quality and guarded-memory evidence. Ordinary bug fixes need not reopen a broad
speed-search project.

## Closeout verification actually performed

- Clean rebuild: `cmake --build build-release --clean-first --parallel 6`,
  Release, MLX 0.32.2 and real tokenizer enabled: **passed**. The existing
  duplicate-static-library linker warning remains; no new runtime source edits.
- `QWEN38_TEST_MODEL="$MODEL_DIR" ctest --test-dir build-release
  --output-on-failure`: **7/7 passed**, including persistent QSA, core, memory
  guard, expert-trace tools, MLX, probe CLI and real-checkpoint tokenizer tests.
- Server/guard CLI help checked against documented startup flags.
- Guarded default-server smoke on isolated port 11439: **not run**. Admission
  returned exit 75 before model startup: 40.4 GiB available versus the unchanged
  42 GiB start requirement. No other application was closed and no guard was
  weakened. Consequently no new API/SSE/recovery, speed or quality result is
  claimed by this closeout. Prior validation remains linked above.
- 71 local documentation links/anchors across nine files and whitespace checked
  before commit; no broken links found. Detailed
  historical tables retained; stale profile/greedy-only instructions corrected.
- Pre-existing edits to `devtools/run_ifbench.py` and
  `devtools/run_mlx_humaneval.py` left untouched and excluded from this commit.

No models, caches or worktrees were deleted. No background service, launch agent,
version tag or deployment was installed. To use the accepted build, free enough
memory and follow the single [operations recipe](operations.md#launch-and-verify).
